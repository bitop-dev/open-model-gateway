# Open Model Gateway: unreleased

Notes for changes on `main` after [v0.19.0](v0.19.0.md). They become the next release's notes.

## Gateway behavior

- The job poller now claims each video, native batch and 0016 batch with an owner, a renewable 60 s lease and a claim epoch on the job row, as the batch runner does for gateway-run batches (#651). Two gateway processes no longer poll the same job at once, and a poller that lost a native batch to another (it stalled past its lease) before it recorded the batch's results writes nothing more to it: it records no status or counts, does not finish or settle it, and deletes the result files it wrote, so a batch no longer gets duplicate, unlinked result files. A poller whose lease lapses after it recorded the results still settles the batch (settlement applies once) and deletes the provider's copies. A submission that fails after its poller lost the claim now ends `submission_interrupted` with its hold kept as unknown, where it could take the free release before. Video and 0016 batch observations are claimed but not fenced: only their state change is compare-and-set, so a stale observation can still rewrite progress, counts and display status with older values. A crashed process's jobs are polled again after about a minute. [Poller](../async-jobs.md#poller)
- **Claude Code on OpenAI-style models: reasoning and structured output** (#70, delivery 3). Messages requests to OpenAI and OpenRouter models now map `output_config.effort`, `thinking`, `output_config.format` and tool `strict` to the provider's own controls instead of dropping or refusing them. OpenAI Chat receives `reasoning_effort` and a strict `json_schema` `response_format`; it has no thinking control, so `thinking` is still dropped there. OpenRouter receives its `reasoning` object, the same `response_format` and `provider.require_parameters:true`, so it routes only to providers that support the sent parameters. Reasoning text returned by OpenRouter and by local reasoning parsers (vLLM, SGLang, Ollama) now reaches Messages clients as `thinking` blocks without a signature, in JSON and SSE, when the request enables thinking without `display:"omitted"`. Chat Completions and Responses clients still never receive it. Claude Code may replay those unsigned blocks: translated routes remove them as before, and a native Anthropic route refuses them with 400 `thinking`, also when the replayed `signature` is empty or blank (before, `"signature":""` was forwarded and refused by Anthropic after admission). When an OpenAI or OpenRouter model declines a structured-output request with a `refusal`, a Messages client now gets `stop_reason: "refusal"` and no content instead of a 502; the refusal text is not returned. Chat Completions and Responses clients still get 502 for a refusal. Local profiles keep dropping reasoning controls and refusing `output_config.format`/`strict`. Bedrock and native Anthropic are unchanged. Reasoning tokens remain inside the reported output count; holds, settlement and missing-usage handling are unchanged. No migration, runtime grant or route changes. [Claude Code field rules](../protocol-matrix.md#claude-code-field-rules)
- **Structured output and strict tools on native Anthropic and Bedrock** (#70). Messages requests to native Anthropic models now forward `output_config.format` and tool `strict` exactly instead of refusing them with 400; both are generally available on the Anthropic API and no beta header is added. Bedrock Converse now receives `output_config.format` as `outputConfig.textFormat` (JSON schema) and `strict:true` tools as `toolSpec.strict`, for Messages, Chat Completions and Responses clients; Bedrock decides per model whether it supports them and returns a validation error (HTTP 400) when it does not. Chat Completions and Responses requests with `strict:true` tools on Bedrock were refused before (HTTP 501 `unsupported_capability`); they are now sent. Reasoning content returned by Bedrock models that reason by default no longer fails the request as an invalid upstream response: it is decoded, counted in the output bound and withheld (thinking cannot be requested on Bedrock, which still refuses `thinking` with 400). Local profiles still refuse `output_config.format` and `strict` with 400; Chat Completions and Responses strict tools on native Anthropic are still refused. No migration, runtime grant or route changes. [Structured output rules](../protocol-matrix.md#structured-output-and-strict-tools-on-anthropic-and-bedrock-routes)
- **OpenRouter strict tools from every client protocol set `require_parameters`** (#70). A Chat Completions or Responses request with a `strict:true` tool on an OpenRouter model now also sends `provider.require_parameters:true`, as Messages requests already did, so OpenRouter routes it only to providers that honour every sent parameter instead of one that may ignore `strict`. What changes for existing Chat clients: such a request can no longer be served by a provider that lacks strict support; if no provider of the model supports every sent parameter, OpenRouter refuses it and the client receives HTTP 400 (`upstream_rejected`) instead of an unconstrained reply. Requests without a strict tool are unchanged.

## Upgrade

No migration or grant change: the claim uses the `runner_id`, `runner_lease_until` and `runner_epoch` columns and grants of 0021 and 0081. The claim protects a job only once every gateway process runs this release. A process of an earlier release still polls with the old 30 s soft claim and ignores the lease, so drain older replicas rather than running them beside this one.
